# 六西格玛黑带教练（six-sigma-coach）

一个面向 Codex 的六西格玛问题分析 Skill。它不会看到问题后立即套工具或给方案，而是像黑带教练一样逐问澄清：先确定应走的改善路线，再定义结果 `Y`、检查测量证据、验证关键原因 `X`，最后形成可执行的改进与控制闭环。

## 它解决什么问题

适用于质量、良率、波动、客户投诉、可靠性、流程改善和产品研发等场景，包括：

- 已有流程或产品长期不达标；
- 客诉、质量逃逸和重大异常；
- 新产品、新流程或系统架构设计；
- DOE、MSA、过程能力、FMEA、QFD、SPC 等工具选择；
- 镜头、成像模组及光机电软系统问题；
- 不确定应该使用 DMAIC、DFSS、8D/CAPA、Lean 还是 PDCA。

它不适合只有一个明确公式的简单计算，也不会在缺少必要输入时用复杂统计工具制造“看起来很科学”的结论。

## 核心特点

### 1. 像黑带教练一样逐问拷问

默认每轮只处理一个真正影响决策的问题：

1. 先说明当前分析路线和阶段；
2. 每次只问一个关键问题；
3. 给出推荐的回答格式，并解释为什么重要；
4. 说明什么证据才足够；
5. 等待回答后再进入下一步。

如果暂时不知道答案，可以直接回答“不知道”。Skill 会把它转换为明确的证据缺口、待验证假设或数据采集行动，而不是虚构数值。

### 2. 先选路线，再选工具

| 问题类型 | 推荐路线 |
|---|---|
| 既有过程存在慢性、重要且原因未知的差距 | DMAIC |
| 新产品、新流程、平台设计或必须根本重构 | DFSS / DMADV / IDOV |
| 客诉、逃逸或重大异常，需要先保护客户 | 8D / CAPA |
| 等待、搬运、库存、换线和现场浪费 | Lean / VSM / SMED / 5S |
| 局部、低风险且原因相对明确 | PDCA / A3 / Kaizen |

Skill 不会强迫所有问题机械走完 DMAIC 五个阶段；当证据表明路线不合适时，它会说明为什么需要切换。

### 3. 设有证据关口

- **Define：** 客户、Y、缺陷定义、基线、目标、范围和业务影响是否明确？
- **Measure：** 数据是否有代表性，测量系统是否足以支持这项决定？
- **Analyze：** 原因是否有可检验的机制、效应量与排除混杂的证据？
- **Improve：** 方案是否作用于已验证的 X，并经过受控试验和独立确认？
- **Control：** 负责人、方法、频次、界限、反应计划和变更控制是否真正落地？

填写完模板不代表通过关口。

### 4. 工具分为三种状态

- **现在使用：** 输入已具备，输出能够改变当前决定；
- **以后使用：** 需要先满足明确的前提条件；
- **暂不使用：** 当前使用只会产生虚假信心。

### 5. 内置统计边界校准

Skill 会主动避免一些常见误用，例如：

- 把控制限当成规格限；
- 把 `Cpk ≥ 1.33` 当成所有场景的统一放行标准；
- 机械套用 `%GRR < 10%`；
- 用正态性检验的一个 p 值决定数据是否可用；
- 把统计显著等同于工程重要；
- 把相关、Pareto、鱼骨图或投票直接当成根因证据；
- DOE 中忽略随机化、重复、区组、混杂、残差和确认试验；
- FMEA 只按 RPN 排序，而忽略严重度和 AIAG-VDA 行动优先级。

### 6. 光学工程扩展

对于镜头、成像模组和 CODE V 相关问题，Skill 会额外检查：

- MTF、SFR、焦距、畸变等 CTQ 的操作性定义；
- 场点、空间频率、Sag/Tan、波长、光圈、物距和温度条件；
- 重装、对焦、夹具、设备、操作者、算法与软件版本造成的测量变差；
- 光学、结构、电子、固件、算法、制造和测试之间的接口；
- 仿真证据、样机证据与量产能力之间的边界。

CODE V 模型结果会被视为特定假设下的模型证据，而不是自动等同于量产能力。

## 安装

将本仓库克隆到 Codex 的 Skills 目录：

```powershell
git clone https://github.com/lsst-optical/six-sigma-coach.git "$env:USERPROFILE\.codex\skills\six-sigma-coach"
```

如果该目录已存在，请先确认其中是否有需要保留的本地修改。安装或更新后，新建一个 Codex 任务；如果技能列表尚未刷新，请重新启动 Codex。

## 使用方法

Skill 支持自动识别，也可以显式调用：

```text
$six-sigma-coach 请用黑带拷问模式分析这个问题：长焦端 MTF 良率最近下降。
每次只问我一个问题，不接受未经证实的根因。
```

也可以要求快速路由：

```text
$six-sigma-coach 先快速判断这个问题该用 DMAIC、8D 还是 DFSS，
列出当前能用的工具、暂时不能用的工具，以及最关键的一个证据缺口。
```

典型的第一轮回复会先声明路线和阶段，然后要求把模糊症状改写为可测量的 `Y`，并给出建议回答格式和证据标准。

## Obsidian 沉淀原则

分析期间默认只读，不会擅自把内容写进知识库。形成共同结论后，Skill 会先展示准备保存的决策记录，并明确询问是否保存；只有用户确认后才会写入。

默认配置的知识库位置是：

```text
G:\obsidian\六西格玛思维
```

如果你的知识库路径不同，请修改 `references/obsidian-capture.md`。公开仓库不包含任何原始培训文件、项目数据或个人项目记录。

## 设计原则

- 事实、推断、假设和决定分开；
- 症状不等于问题定义，相关不等于因果；
- 只有输入可靠且输出会改变决定时才使用工具；
- 结论同时说明效应、不确定性、工程意义和适用边界；
- 高风险事件先遏制，再进行完整根因分析；
- 最终输出必须包含负责人、下一项证据和阶段关口。
